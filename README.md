# 分纤箱布点估算工具

本地单机网页工具：从村庄地图或客户 DWG 转换出的 DXF 中提取民房、道路、进村点和已有箱，人工复核后自动估算分纤箱数量、杆数和主干光缆长度，并输出 PNG、CSV、DXF 和工程 JSON。

## 使用

双击 `index.html` 用 Chrome 或 Edge 打开即可，不需要联网或服务器。

### CAD 快速导入

1. 使用 ODA File Converter 等工具把客户 DWG 转为 ASCII DXF。Windows 已安装 ODA 时，可把一个或多个 DWG 拖到项目根目录的 `转换DWG.cmd`；转换结果默认保存在原 DWG 旁的 `DXF-output` 文件夹，同名文件不会被覆盖。
2. 点击**导入 DXF**选择文件。
3. 在识别预览中检查户点、道路段数、路网分量、入口、箱、杆位、“缺口补桥”和户点到路网距离。橙色虚线代表程序推断的补桥，红圈代表远离当前路网、需要复核的户点。
4. 如图纸有明确语义图层，可分别指定道路、民房、已有箱、新设箱和电杆图层；道路可选择“自动判断 / 已有中心线 / 双边线”，离路复核阈值可按图纸单位调整。
5. 图纸使用固定图块但没有统一文字时，展开“图块名称规则”，填写民房、已有箱、新设箱、电杆或进村点的完整图块名，再点击**重新识别**。
6. 选择**确认导入**保留识别结果，或选择**取消导入**恢复原工程。
7. 使用路网、户点、进村点、已有箱和**删除**工具补充或删除误识别对象；误删后可点**撤销**恢复，推断补桥身份也会一并恢复。
8. 用**比例校准**沿已知距离点两个点并输入实际米数。
9. 设置覆盖距离、每箱户数、杆距和估算模式，点击**计算布点**。
10. 导出 PNG 标注图、CSV 清单或 DXF 示意图；工程可保存为 JSON。

### 图片人工标注

1. 点击**导入地图**加载带比例尺的村庄工程图或截图。
2. 完成比例校准。
3. 沿道路画路网，补充户点、进村点和已有箱。
4. 设置参数并计算、复核、导出。

## DXF 自动识别规则

- `民房`、`房屋` 或 `房屋+编号` 文字识别为户点；`道路`、`村道`、`乡道`、`街道+编号` 作为道路几何参考。
- `光交` 或 `配线层` 文字作为进村点参考。
- 分纤箱和电杆文字按现有命名规则部分识别；CAD 杆位和图中计划箱位目前只作为参考显示。
- 长平行道路双边线会配对生成中心线，支持水平、垂直和斜向 `LINE`，也支持仅含两个顶点、实际表示直线的 `LWPOLYLINE`；带转角的房屋轮廓不会进入这条配对规则。
- 同一交叉口附近的中心线端点会聚类到同一节点，以避免肉眼不可见的断路。
- 识别中心线沿端点原方向遇到另一道路时，会尝试补齐短缺口；推断补桥以橙色虚线显示并单独计数，必须人工复核。
- 自动模式会统一排除图例、说明、图框和模板图层中的民房、道路、入口、箱和杆标注；用户显式选择某个语义图层时以该选择为准。
- 图块名规则按完整名称、忽略大小写匹配；填写后，该角色只采用匹配 `INSERT` 的插入点。已有箱和新设箱使用独立图层与规则，不会互相改写。
- 指定道路图层并选择“已有中心线”时，直接使用该图层中的 `LINE`、`LWPOLYLINE` 和 `ARC` 中心线候选。
- 自动判断或双边线模式不会直接把道路图层中的 `ARC` 当作中心线，因为它们可能是道路边界的转角圆弧；预览会显示未采用的圆弧数量。
- 默认以 30 图纸单位检查户点到最近道路的距离，预览显示阈值内数量、中位距离和最远距离；超过阈值的户点以红圈标记，补画道路或删除误识别户点后会自动刷新。
- 自动识别是启发式结果。图框、房屋轮廓、尺寸线和引线不能一概视为道路，必须在预览和画布中复核。

## 计算口径

- 户到分纤箱按**直线距离**计算；主干光缆按**道路图上的最短路径并集**计算。
- 默认每箱 16 户、覆盖距离 100 米、杆距 50 米，均可调整。
- 光缆长度不含到户皮线。
- 有箱补点模式中，已有箱覆盖距离内的住户视为已覆盖且不占新增箱容量，仅为未覆盖住户布置新箱。
- 杆数 = `ceil(主干光缆长度 / 杆距)`。
- 补点模式同时输出主干光缆总长和新增光缆长度。
- 断开的箱位不会被计入有效覆盖，界面会给出路网不连通警告。

## 输出格式

- **PNG**：全分辨率标注图，包含箱位、覆盖圈、路由、杆位、户点归属、橙色虚线推断补桥和未处理的红圈离路户点。
- **CSV**：工程量汇总和每箱明细，可直接用 Excel 打开。
- **DXF**：R2000 米制文件（`AC1015`、`$INSUNITS=6`），分 `ROAD/CABLE/BOX/EXIST/POLE/HOUSE/ENTRANCE` 图层的估算示意图。
- **工程 JSON**：地图、标注、参数、结果、推断补桥索引和离路复核阈值；浏览器也会自动暂存最近工程。

## 开发与验证

```powershell
node tests/core.test.js
node --check app.js
node --check core.js
node --check dxf-lite.js
node --check cad-import.js
```

可选的 DWG 转换助手也可直接从 PowerShell 调用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\convert-dwg.ps1 -InputPath "D:\图纸\村庄.dwg"
```

如未自动找到 ODA，可增加 `-OdaPath "C:\路径\ODAFileConverter.exe"`；用 `-OutputDirectory` 可指定输出目录。助手在隔离临时目录中逐个转换文件，启用 ODA 审核，输出 ACAD2018 ASCII DXF，并避免覆盖已有同名结果。网页本身仍不依赖 ODA。

## 目录

- `index.html` / `style.css` / `app.js`：界面、画布交互、导入事务和导出。
- `dxf-lite.js`：轻量 ASCII DXF 实体解析。
- `cad-import.js`：CAD 语义识别、道路双边线配对和端点吸附。
- `core.js`：路网建图、Dijkstra、箱位选择、光缆路由、工程量计算和 CSV/DXF 生成。
- `转换DWG.cmd` / `tools/convert-dwg.ps1`：可选的 Windows 本机 DWG→DXF 转换助手。
- `tests/core.test.js`：核心算法、DXF 解析和 CAD 识别回归测试。

## 当前边界

- 网页不能直接解析 DWG，必须先转换为 DXF；附带助手仅在电脑已安装 ODA File Converter 时可用，不是网页运行依赖。
- DXF 解析器尚未展开块定义中的嵌套实体；`ARC` 仅在显式“已有中心线”模式中转为路网，双边圆弧配对、样条和椭圆仍不支持。
- 没有统一文字、图层或图块规则的图纸仍需要配置图层或人工修正。
- DXF 导入后仍需比例校准；不能仅凭图纸单位声明推断实际米制。
- 离路复核阈值使用 CAD 图纸单位，只用于发现漏识别道路或异常户点，不等同于校准后的户到箱覆盖距离。
- 输出 DXF 是估算示意图，不含测量坐标精度，不能作为正式施工图或现场放线依据。
- 不包含服务器部署、多人在线协作或 GIS 坐标系处理。
